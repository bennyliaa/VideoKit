## 仓库内容与边界

纳入项目工程源码/配置、设计需求/Schema/追踪表、历史文档、开发测试报告，以及可安全入库的自有候选源码/工具和小型证据元数据。保留原始字节与来源hash，不将第三方分发包/构建缓存、用户test_media、大型生成二进制/原始采集流、local.properties、密钥/凭据推送。排除只影响Git，不删除本地文件或篡改旧manifest；报告引用的本地归档/依赖可能未随Git发行，不能声称Git快照可独立复现全部历史二进制或已获得其再分发权。

## tester后续按需提交（用户明确恢复后）

- tester在整批验收/集中修复回归后，按需提交该候选源码、对应文档/报告和来源清单；不按每个问题或用例提交，不机械重复编译。
- 提交前核对git status/diff、准确候选来源/manifest、当前分支和允许文件清单；只stage本批明确文件，禁止git add .夹带其他批次或他人浮动改动。coder冻结期间不修改源，tester不能把已测源码换成未测新字节再称同候选通过。
- main保存可追踪已审核快照，不等于产品稳定版。通过的批次按负责人正式安排合入；未通过但需保存的代码/测试证据用明确标识的review/WIP分支，报告保留FAIL/NOT_RUN/UNKNOWN，不打stable/release标签。
- 后续默认以整批分支/PR交负责人审核；如用户/负责人已明确授权直接提交指定分支，可按该授权执行。不得force push、改写历史、覆盖别人的提交或自动发布；远端有新提交先审差异，不盲目重置。
- commit message写明批次/改动与验证范围，提交后记录SHA/分支/远程URL及未运行项；push前再次排查密钥、媒体、第三方许可和大文件。提交权限不等于可启动测试/调用设备或处理旧UNKNOWN。
- 当前暂停期间不让tester新开任务；本次负责人仅写入流程并完成用户指定仓库同步，不向暂停的coder/tester派发开发测试。
