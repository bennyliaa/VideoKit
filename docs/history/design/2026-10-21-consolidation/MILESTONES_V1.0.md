## 1. 设计门禁

本轮交付第 30 节十份草案及 App 架构、评审索引。用户已确认 App 使用 Flutter，展示编辑入口和多画面 UI，全部需求功能按顺序完成于一个完整 V1.0。以下均为同一版本内部的开发与验收阶段，不代表多个功能版本。用户整体设计评审通过后才进入大规模编码。关键选择通过局部 Spike 证明可行，不把草案当已批准事实；许可和 API 未冻结前禁止多个实现沿不同契约扩张。

## 3. 原文第 29 节逐项冻结

| 项 | 当前建议 | 冻结证据与替代方案 |
| --- | --- | --- |
| 1 group/artifact/namespace/version | 拆 API 与功能 artifact；SemVer | 用户确认合法命名与发布渠道；现有 com.videokit.app 不等于已批准公司 namespace |
| 2 播放/编辑拆包 | 必须可分别使用 | 依赖图、纯播放包无 AI/编码依赖 |
| 3 播放/图像/编码组件 | Media3 + 平台媒体框架；libmpv不列正式候选/对照 | 格式/输入/Sink Spike、锁版本、许可清单 |
| 4 跟踪/模型/设备 | OpenCV + YuNet/ViTTrack 候选 | 模型权利、质量与 ARM64 性能；运行时 DNN/ORT 对照 |
| 5 输出与预设 | MP4/H.264/AAC/SDR 候选 | 真机编码、专利/格式审查；不支持设备明确反馈 |
| 6 无重编码条件 | 技术参数/轨道/关键帧/PTS 兼容 | 正反样本、remux 与转码对照 |
| 7 指标 | 尚未冻结 | 数据分布、漏码安全门禁、设备分级 |
| 8 UI/纯引擎组合 | 原生纯引擎 + Compose/View；App Flutter 已确认 | 纹理、多实例、编辑 UI 和原生接入实测 |
| 9 Sink 能力 | 显式顺序/随机/flush/close/验证 | 实际 muxer 要求、未知长度/空间、受控暂存方案 |
| 10 Schema/恢复 | 版本化 JSON、微秒与归一坐标 | 迁移/源指纹变更测试；编码任务可从头重启 |
| 11 控件/主题/叠加 | 共用交互规范，各 UI adapter | 触摸/桌面/无障碍、controlsVisible 与宿主面板 |
| 12 池与预算 | 宿主范围管理器、预留后创建 | 资源引用计数、并发/热/失败反馈；不能信任声明值 |

新增需评审：四平台 OS/CPU 架构；原生崩溃隔离可行性；原生 Kit 与 Flutter UI 的维护边界；原生格式缺口在既定平台路线的处置方案；libmpv不再列正式候选/对照。正式 App 编辑入口与多画面 UI 已确认，属于完整 V1.0。

## 4. coder/tester 工作边界

coder 在冻结契约下提交模块设计、依赖审查、实现和失败可恢复行为；tester 独立按需求追踪进行契约、真机、编辑输出、跟踪效果与安全测试。需求助理维护变更、风险与退出条件。任何角色不得自行把人脸/物体自动跟踪、输出安全或原生宿主兼容移到后续。

用户已授权负责人协调现有 VideoKit coder 和 VideoKit tester；当前派发D1，按完整里程碑开发、自检、整包交接和独立验收顺序推进。所有阶段分别提供技术与测试需求，见 [里程碑协调与文档总表](MILESTONE_COORDINATION_V1.0.md)。Apple/Windows阶段暂不派发。

coder完成当前里程碑全部范围再一次性交tester；缺陷按批次修复和回归，不按小功能频繁交接。编译按完整功能簇集中执行，保留首次基线、关键依赖/API/原生绑定和候选集成的必要检查，不重复无变化的构建。正式候选测试期间冻结源码和产物。
