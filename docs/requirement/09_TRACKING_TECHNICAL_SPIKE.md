# 09 跟踪技术 Spike

版本：V1.0；日期：2026-11-06；对应原需求 §10.5–§10.7、§22、§23、§26.6。

自动跟踪是 P0 中技术风险最高的部分。本文件先定义 Spike（技术验证）方案，Spike 通过后再进入 VK-M5 正式实现；Spike 与 VK-M1–M3 并行进行（见 [12](12_MILESTONES.md)）。

## 1. 目标

1. 人脸：检测一个或多个人脸 → 用户选择目标 → 区间内跟踪 → 短时遮挡/出画后尝试重关联。
2. 物体：用户点选/框选 → 跟踪位置、大小与必要的形变边界 → 多目标（按设备能力限并发）。
3. 不确定性显式化：每段结果带状态 TRACKED / LOW_CONFIDENCE / AMBIGUOUS / LOST。
4. 纠正：任意关键帧重新指定目标，从纠正点重新计算后续轨迹。
5. 安全：导出前未覆盖区间检查，绝不静默漏码。
6. 全部本地处理，不上传，不建永久人脸库；目标身份只在当前工程内用于关联。

## 2. 候选方案

| 能力 | 路线 A（首选） | 路线 B（对照） |
| --- | --- | --- |
| 人脸检测 | OpenCV Zoo YuNet | 平台/其他许可合适的检测模型（Spike 中确定） |
| 物体跟踪 | OpenCV Zoo ViTTrack | OpenCV 传统跟踪（如 CSRT/KCF）+ 周期重检测 |
| 多目标与重关联 | 自研编排：检测 + 跟踪器 + IoU/外观相似度关联（SORT 类思路） | 同左，参数不同 |
| 推理运行时 | OpenCV DNN | ONNX Runtime（CPU，再评估 NNAPI/GPU provider） |

候选的代码与模型许可、训练数据权利需要逐项核查（[10](10_OPEN_SOURCE_AND_LICENSE_PLAN.md) 第 4 节）；权利不清的权重不能进入产品。

## 3. 处理流程

```text
源（只读）→ 帧提取（指定区间，按分析分辨率解码）→ 方向/色彩归一
 → 检测候选 → 用户选择 targetId
 → 逐帧：跟踪器更新 + 周期性重检测 → 关联与置信估计
 → 输出 TrackingResult：每帧 {atUs, region, confidence, state}
 → 生成覆盖报告 CoverageReport：按区间列出 TRACKED / LOW_CONFIDENCE / AMBIGUOUS / LOST
```

- 分析分辨率可低于源分辨率以节省成本，结果映射回归一化坐标；遮罩可按置信度保守外扩（外扩策略在 UI 中可见）。
- 只有实际分析过的帧才能算“覆盖”；跳帧分析时未分析帧不能断言已覆盖，最终导出前按输出帧 PTS 复核。
- 遮挡或相似目标靠近时标 AMBIGUOUS/LOST，不擅自切换目标身份。
- **多人场景的身份保持**（2026-11-07 补充，打码与头像替换共用）：片段中多人走动、交叉、遮挡、背身、出画再入画时，被选中的目标必须始终是同一人。关联打分综合：运动预测（位置/速度，Kalman 类）、人脸特征（如 SFace，权重许可待核）、躯干衣着颜色直方图（HSV，仅作人脸不可见时的辅助，不能单独决定身份）与 IoU。任一线索不足以确认时标 AMBIGUOUS/LOST 交用户确认；用户在该区间重新选中目标后从该点重算。S6 按场景统计 ID switch 与“应标未标”（漏标）率。
- **头部姿态**（头像替换用，REQ-ED-07）：人脸目标的关键帧可带可选 `rollDeg`（双眼连线角度），供头像“随头部转动”；头部区域由人脸框按比例扩展（含头发），比例在 S6/S7 中给出。
- 纠正关键帧使该点之后的结果失效并重新计算；结果带 `projectRevision` 与 `requestId`，过时的计算结果被丢弃。
- 跟踪任务在隔离 worker 中运行，可取消；模型缺失、内存不足、热降级时返回稳定错误，播放与手动编辑不受影响。

## 4. 与编辑和导出的衔接

- 跟踪结果写入 `MaskTrack.keyframes`（source=TRACKER），用户可继续手动修改（source=USER 优先）。
- 时间线以颜色加图标显示每段状态；LOST/AMBIGUOUS 区间可一键跳转并纠正。
- 导出前 `checkExport` 强制检查：任一启用的自动遮罩存在 LOST/AMBIGUOUS 或未分析区间时，阻止导出并列出区间；用户可选择：纠正、对该区间改用手动关键帧、对该区间改全帧打码，或明确确认接受（确认记录在导出警告中，结果不得标为“完整打码”）。

## 5. 测试集与指标

### 5.1 测试集

自建有许可并人工标注的样本，分别覆盖：单人、多人、侧脸、遮挡、低光、快速运动、出画重入、相似目标、低对比、竖屏、横屏、高分辨率（4K）、多目标。训练/调参数据与验收数据分开。样本与标注有来源和许可记录，不使用来源不明的人物素材。

### 5.2 指标

| 类别 | 指标 |
| --- | --- |
| 检测 | precision、recall（按人脸尺寸分档） |
| 跟踪 | 跟踪丢失次数、ID switch（错误关联）、边界 IoU、未覆盖帧数（真实目标未被遮罩覆盖的帧） |
| 交互 | 每分钟视频需要的纠正次数、纠正后恢复率 |
| 性能 | 处理速度（相对实时倍数）、首个结果耗时、峰值内存、CPU、温度、电量 |

厂商 README 中的指标不能当作本产品验收值。阈值在 Spike 后由负责人与用户评审冻结，未冻结前不得宣称“跟踪可靠”。

## 6. 隐私

- 模型随安装包或由用户在本地导入，默认不联网下载；运行时禁用遥测，并以断网测试验证不发起网络请求。
- 不保存人脸图像或特征到工程以外的位置；工程中只保存区域坐标与状态。
- Release 不记录用户轨迹日志。

## 7. Spike 退出材料

1. 两条路线的对比报告（质量指标、性能、许可结论）与推荐方案。
2. 固定版本、模型 hash、模型与数据权利清单。
3. ARM64 手机与平板上的 CPU / 加速兼容和资源报告，建议的最低设备。
4. 可交互原型：选择目标、跟踪、LOST 提示、纠正、重新计算。
5. 取消、内存压力、热降级测试结果。
6. 阈值建议及误报/漏报权衡。

质量不达标时如实报告，并提出替代方案（换模型、缩小首版支持场景须经用户批准，不能自行降级 P0）。
