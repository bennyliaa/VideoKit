# 01 产品需求

版本：V1.1；日期：2026-11-06；依据：原需求 V1.0 全文与用户 2026-11-06 决定（UI 用 Flutter、自有 Theme）。本文件把原需求整理为可编号、可追踪的条目，不删减原文；如有出入，以原需求正文为准。

## 1. 产品定位

VideoKit 是可复用的媒体播放与编辑能力库，不是 NAS 浏览器，也不是 LocalVideoBrowser 业务模块（§2）。首期以 Android AAR 为正式交付目标；领域模型、时间线和编辑计划与 UI 及具体解码器隔离。UI 优先使用 Flutter 开发，为以后其他 App 或其他平台保留可能；本阶段不承诺 iOS、macOS、Windows 交付时间。

**术语：VideoKit 模块 与 VideoKit App（2026-11-07 用户确认，全部文档按此区分）**

| 术语 | 是什么 | 使用者 |
| --- | --- | --- |
| **VideoKit 模块** | 可复用的实现内核：原生 Kit（`kit/` 下全部模块，AAR）+ Flutter 包（`videokit_api`、`videokit_ui`、`videokit_flutter`）。本套需求与设计文档描述的能力、API、界面组件都属于模块 | VideoKit App；LocalVideoBrowser 等宿主 App 集成使用 |
| **VideoKit App** | 独立发布的视频播放 App，即 [UI 设计稿](VideoKit_UI_Design_V1.0.pptx) 所示的 App；以 VideoKit 模块为内核，按原需求提供播放、图片查看、多画面、编辑、打码跟踪、导出功能 | 最终用户 |

- VideoKit App 是 VideoKit 模块的第一个宿主，和 LocalVideoBrowser 一样只通过公共 API 与扩展点使用模块，不使用模块内部实现；凡是 App 需要而模块没有的能力，应补进模块的公共 API，而不是在 App 里绕过。
- VideoKit 模块不依赖 VideoKit App；LocalVideoBrowser 集成模块时不需要 App 的任何代码。
- 在 SkinKit 中，VideoKit App 是一个宿主 App（`appId = videokit`）；VideoKit 模块嵌入其他宿主时跟随宿主主题（[03](03_UI_FRAMEWORK_DESIGN.md) §5.5）。
- VideoKit App 自身需要、但不属于模块的部分只有 App 外壳：启动与导航、打开媒体的入口（系统文件选择器 + 系统“打开方式”，2026-11-07 确认）、权限、设置、关于；需求见 §4.13。
- `videokit_example` 是模块的开发示例（含演示场景面板、宿主扩展点示例），不是 VideoKit App。

## 3. 使用场景（§3）

- **LocalVideoBrowser 用户**：从本地或 NAS 浏览，点击媒体后由 VideoKit 全屏播放或查看；播放页可触发标签、收藏和编辑。
- **其他宿主 App**：只用播放、只用编辑，或同时使用；不要求宿主建立 LocalVideoBrowser 的数据表、目录或 NAS 环境。
- **未来独立 App**：以 VideoKit 为底层能力；媒体库、文件选择、账号、业务导航不进入核心库。

### 4.13 VideoKit App（APP）

VideoKit App 是以 VideoKit 模块为内核的独立视频播放 App（§1 术语），界面以 [UI 设计稿](VideoKit_UI_Design_V1.0.pptx) 为准。以下只列 App 外壳需求；播放、图片、多画面、编辑、打码、导出等功能由模块提供，App 通过公共 API 使用。

| ID | 需求 | 级别 | 依据 |
| --- | --- | --- | --- |
| REQ-APP-01 | 打开媒体：通过**系统文件选择器**（`ACTION_OPEN_DOCUMENT`）选择视频或图片（可多选，用于多画面与多视频拼接），打开时申请长期访问授权（`takePersistableUriPermission`），以便从播放记录再次打开；不扫描设备、不建媒体库，不申请宽泛存储权限 | P0 | 用户 2026-11-07 确认 |
| REQ-APP-02 | 系统“打开方式”：在文件管理器、相册等应用中选“用 VideoKit 打开”（Android `ACTION_VIEW` / `ACTION_SEND` 的视频与图片类型）直接进入播放器或图片查看器 | P0 | 用户 2026-11-07 确认 |
| REQ-APP-03 | 读取经系统授予的 Content URI，只读；导出结果经系统“另存为”（`ACTION_CREATE_DOCUMENT`）写到用户选择的位置，不覆盖源文件 | P0 | 原需求 §11、§22 |
| REQ-APP-04 | App 外壳：启动、导航、设置（主题深浅色、语言、减少动画等）、关于与开源许可页 | P0 | 用户 2026-11-07 |
| REQ-APP-05 | App 只经公共 API 与扩展点使用模块；App 需要的能力先补进模块公共 API | P0 | 用户 2026-11-07 |
| REQ-APP-06 | Release 构建不含 Fake 与演示资源；SkinKit 宿主接入（`appId = videokit`）在 SkinKit v2.0 支持 Flutter 后安排 | P0 / 后续 | 用户 2026-11-07 |
| REQ-APP-07 | **最近播放（App 首页）**：记录打开过的媒体——视频记名称、时长、缩略图、上次播放位置、最后观看时间；图片记名称与最后查看时间；多画面/拼接一次打开多个文件时每个文件一条。点击从上次位置续播；支持列表/网格视图、单条删除、全部清空。文件已删除、移动或授权失效时标为“无法打开”并提供“重新选择文件”。记录上限 200 条，删除条目或超出上限时同时释放对应的长期授权。从“打开方式”进入的条目也记录，授权为临时时提示可能需要重新选择 | P0 | 用户 2026-11-07 确认 |
| REQ-APP-08 | 播放记录的隐私：只保存在 App 私有目录，不上传；设置中提供“记录播放历史”开关（默认开启）与“清空播放记录”；缩略图只存小尺寸，清空记录时一并删除；不记录媒体内容本身 | P0 | 用户 2026-11-07；原需求 §22 |

播放记录属于 **App 业务需求**，由 VideoKit App 实现与保存，不进入 VideoKit 模块（模块不保存用户操作记录，原需求 §22）。续播使用模块已有能力：会话关闭时 App 调用 `captureState()` 取播放状态快照并保存，再次打开时作为 `bind(initialState = …)` 传回模块（[04](04_PUBLIC_API_CONTRACT.md) §3），模块无需为此增加接口。

## 5. 不在首版范围

复杂转场、滤镜、调色、文字贴纸、图片编辑与图片转视频（后续）；云端 AI、素材云同步（不做）；iOS/macOS/Windows 实现（不承诺时间）；宿主业务（NAS、标签、收藏、VideoBox、文件事务）始终不属于 VideoKit。
