# 11 测试与验收计划

版本：V1.1；日期：2026-11-06；对应原需求 §26、§27、§31。

## 1. 原则

- 结果只用四种：PASS、FAIL、NOT_RUN、BLOCKED。没有样本、设备或权利证据的项标 NOT_RUN 或 BLOCKED，不伪造 PASS。
- UI 演示（Fake 驱动）结果与真实能力结果分栏记录；演示 PASS 不等于功能 PASS。
- “模型运行完成”“代码已编译”不能代替效果验收。
- Fake 与真实实现执行同一套契约测试。

## 3. 测试矩阵

### 3.1 契约（§26.1）

API 版本与能力协商；旧快照读取与新增可选字段兼容；未知未来主版本安全拒绝；正常、取消、超时、重复调用与 release 幂等；HostAction 超时/失败不影响播放；输入句柄与 Sink 故障映射。

### 3.2 播放（§26.2）

0%、25%、50%、90%、接近结尾 Seek；连续快速 Seek；暂停、恢复、结束、重播；字幕、音轨、倍速、方向、缩放与状态恢复；小视频、2GiB 以上、长视频、损坏、0 字节、播放中断线；每种正式容器（mp4、mkv、mov、avi、webm、m4v、ts、m2ts）至少一个真实有效样本，缺样本 NOT_RUN；释放后句柄归零。

### 3.3 图片（§26.3）

jpg/jpeg、png、webp、heic/heif、avif、bmp、gif；静态 WebP、动态 WebP、动态 GIF；小图、大图、长图、透明图、旋转元数据图、损坏图；左右导航请求、缩放、平移、旋转、窗口变化与释放；无视频专属控件。

### 3.4 多实例（§26.4）

1、4、9、12 槽；视频/静态图/动态图混排；每格状态独立；唯一音频与全静音；离屏暂停/释放与重新绑定；解码器不足、内存压力、温度升高时稳定降级；单槽故障不影响其他槽。

### 3.5 编辑与导出（§26.5）

单视频多片段添加、裁剪、删除、重排；同参数与不同参数拼接；横竖屏、可变帧率、不同音频参数、无音频；手动马赛克/模糊与坐标映射；导出取消、空间不足、权限失败、输入断线、编码器失败、进程被杀；失败后源字节与路径不变；不完整输出不 markReady；宿主验证失败后不提交、不删源。

### 3.6 自动跟踪（§26.6）

单人、多脸、侧脸、遮挡、离开/进入画面；单物体、多物体、快速运动、低对比、相似目标；关键帧纠正与从纠正点继续；丢失区间提示；预览与导出遮罩一致；取消、模型缺失、内存不足、热降级；不产生网络上传或永久人脸资料。

### 3.7 宿主集成（§26.7）

见 [05](05_LOCALVIDEOBROWSER_INTEGRATION.md) §10。

### 3.8 UI 框架（VK-M0）

全部 Flutter 界面可操作；Fake 场景可触发与重置；宿主扩展点示例（Flutter 宿主与原生 add-to-app 各一）；演示标识常驻；Release 不含 Fake 与演示资源；无硬编码样式与文案；Theme 浅深色与宿主覆盖。

### 3.9 设备与环境矩阵（§26.8）

| 维度 | 覆盖 |
| --- | --- |
| Android 版本 | API 31（最低）、一个中间主流版本、当前稳定版本 |
| 设备 | ARM64 实体手机；10 英寸级实体平板（或明确记录的等价设备） |
| 形态 | 竖屏、横屏、分屏、窗口变化 |
| 字体 | 100%、130%、200% |
| 语言 | 简体中文、伪本地化、RTL 冒烟；英文在 VK-M6 后加入 |
| UI 效果 | 逐页对照 [VideoKit_UI_Design_V1.0.pptx](VideoKit_UI_Design_V1.0.pptx) 的效果图与标注：布局结构、元素与状态齐全、配色与层级一致（不做像素级比对，见 [03](03_UI_FRAMEWORK_DESIGN.md) §5.4） |

可用设备及型号在每个里程碑测试前登记。

## 4. 测试样本

- 样本库：`D:\CodexProjects\VideoKit test-workspace\test_media`（只读，不打包、不上传）。现有覆盖：9 种视频容器小样本、9 种图片格式样本、4 个较长 MP4、带中文字幕的 AVI、2GiB 以上 MKV、损坏与 0 字节文件。
- 缺口：动态 WebP、长图/大图/透明图/旋转元数据图、多音轨、内嵌字幕、可变帧率、跟踪标注集等需补充；补充样本记录来源与许可。
- 自动化测试使用的小型夹具由脚本生成并入库（需许可明确）。

## 5. 需求追踪

- 每个 `REQ-*`（[01](01_PRODUCT_REQUIREMENTS.md)）至少映射一个测试用例 `TC-<域>-<序号>`。
- 追踪表 `docs/requirement/TRACEABILITY.csv` 在 VK-M0 建立，字段：REQ ID、原需求章节、TC ID、测试层次、所属里程碑、结果、证据位置。
- 每个里程碑退出时，该里程碑范围内的 REQ 全部有结果；NOT_RUN 与 BLOCKED 需写明原因并经负责人确认。

## 6. 里程碑交付与测试流程

1. 开发完成整个里程碑范围并自测，提交候选：版本号、源码 commit、构建产物与 SHA-256、自测结果、已知问题。
2. 测试在冻结的候选上独立执行，测试期间不改代码。
3. 缺陷汇总为一批，开发集中修复，出新候选，测试执行回归。
4. 测试报告列出每个 REQ/TC 的结果、证据与环境；UI 演示与真实能力分栏。

## 7. 发布阻断检查（§27）

| 阻断项 | 检查方法 |
| --- | --- |
| 可能覆盖、移动、删除输入源 | API 审查（无写源入口）；故障注入下比对源文件 hash 与路径 |
| 输出绕过 Sink 或宿主验证 | 静态检查文件写入调用；导出测试只在 Sink 中出现输出 |
| 凭据、完整路径、宿主类型进入公共 API | api 模块依赖与签名审查；日志与错误脱敏检查 |
| 单会话故障拖垮宿主或误释放其他会话 | 多槽故障注入；资源报告核对 |
| 多实例无法限制音频，或资源不足时循环创建解码器 | 音频与预算测试；压力下统计解码器创建次数 |
| 跟踪丢失仍宣称完整打码 | 覆盖检查测试；导出警告核对 |
| 失败后留下标记成功的部分输出 | 导出失败/取消/杀进程后检查 markReady 记录 |
| 稳定复现 ANR、OOM、泄漏、无法取消的任务 | 长稳测试、泄漏统计、取消时限测试 |
| GPL/AGPL/SSPL 或许可不明代码进入产品 | 许可扫描、MANIFEST 审查 |
| Release 含测试凭据、真实 NAS 资料、压力入口、永久调试日志 | Release 产物扫描 |
| AAR 无法独立构建或宿主须依赖源码 | 用已发布 AAR 与 Flutter 包构建 sample-host、`videokit_example` 与 Browser 适配器 |

任一阻断项 FAIL 或 NOT_RUN，不得发布正式版本或交给 Browser 正式集成。
