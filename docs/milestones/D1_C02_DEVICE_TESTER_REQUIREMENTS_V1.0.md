## 执行顺序

1. 独立核查APK/源码/证据hash与版本，确认compileSdk36.1、minSdk31、unsigned Release和debug技术验证性质；核对47条局部断言及其限制，不重复无必要构建。
2. 检查已授权ADB连接及型号/API/ABI/空间，指定序列号。用户现在被通知开启手机/平板USB调试；未授权/未连接时先完成证据核查并保存明确待设备状态，不能冒充真机结果。读取现有目标包状态，避免安装覆盖用户已有正式应用数据；若同包已有不可确认用途的数据则先报负责人。
3. 仅安装冻结Debug与androidTest包，按设备请求授权目标复制四项fixture（约3.95GB，总可用空间建议至少5GB），电脑test_media只读。若空间不足先做小集合，将大MKV项记NOT_RUN。不得全设备扫描或修改共享存储。
4. 手机、平板按A–F批次分别运行12方法与人工观察：播放/字幕/Seek、实际编码、Sink故障/未知ready、隔离worker退出/超时、平台人脸可行性。保存每设备独立日志与结果，不把一台PASS推广另一台。
5. 核对中文SRT/ASS选择开关、Seek后的字形/同步/画面、导出帧与音频等人工项。工具不能直接观察时明确需用户操作/确认，不凭READY/position/cue计数判视觉通过。
6. worker仅允许杀自身测试进程；8MiB压力不是OOM，broker探针不是实际媒体管线隔离。没有入口的真实编码中取消/宿主kill/多槽存活/标注质量等记NOT_RUN/BLOCKED，不执行全局OOM、不杀其他应用。
7. 更新C01缺口在C02中的处理证据，尤其close失败、非协作provider、ready未知恢复、工具漏洞16命中和模型权利。独立判断可验证范围，元数据缺项清零不是全部合规。
