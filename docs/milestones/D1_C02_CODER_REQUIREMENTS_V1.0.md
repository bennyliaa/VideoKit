# D1 集中补齐开发任务（C02）

版本：V1.0；日期：2026-10-05；状态：当前派发；不进入M0。

依据：[D1开发需求](D1_CODER_REQUIREMENTS_V1.0.md)、[C01交付](../coder/D1_DELIVERY_D1-20261005-C01.md)、[协调规则](../MILESTONE_COORDINATION_V1.0.md)。C01是已冻结但未达到正式验收条件的证据包，不是D1完成声明。

## 1. 集中补齐范围

1. 保留C01复制产物与源码快照不变；工作源码允许本轮补齐，创建新candidateId。tester本轮只核查C01冻结证据，不依赖正在变化的工作树，不运行Gradle或设备。
2. 实现受控可取消异步读取→同步Media3桥：独立I/O执行器、deadline、在途操作排空、open/close竞态、generation淘汰、非协作provider的限制及稳定错误；补齐多消费者资源释放查询。不得把协作假transport的单次耗时当Android/NAS保证。
3. 补齐OutputSink任务ID查询、ready响应未知的幂等恢复及取消仲裁；准备真实Transformer输出、授权descriptor/muxer和输出重开验证。Sink失败路径保留源不变且不错误ready；禁止暗中任意暂存。把实际编码/容器验证和复制样本实验明确分开。
4. 实现最小受控worker/broker隔离原型：每任务归属、有界数据传输、death/cancel/timeout清理。准备worker退出/崩溃/资源压力验证入口。必须区分不同进程同UID与isolatedProcess权限隔离；不将try/catch当原生崩溃隔离，也不为用户终止无关进程。
5. 在同一真机验证包中补齐本地/大MKV/新增AVI、内嵌ASS与外部中文SRT多源路由、字幕选择/关闭/Seek；新增媒体不要按文件名推断编码。字幕已存在，不再将所有字幕样本记为缺失；双音轨/动态图/跟踪标注等缺口单列。
6. 完成依赖许可缺项和NOTICE复核、实际产品runtime与工具依赖分栏、已知漏洞检查。compileSdk37.2超AGP已测范围的警告提出兼容处置建议，集中验证后决定使用已兼容版本或明确证据，不隐藏警告或不必要升级。
7. 对YuNet/ViTTrack训练/预训练来源与权重商用再分发继续查官方证据，比较无需第二权重的传统跟踪路线。证据不足仍禁止纳入产品；若存在合法可用路线，完成D1所需局部离线推理/纠正/LOST实验。不得擅自把自动跟踪P0删除。缺权利或人工标注确实无法解决时，提交具体缺失材料、已查来源、备选及需负责人决定的事项，不能泛泛写“待确认”。
8. 将全部真机需求集中成一个DEVICE_TEST_REQUEST：手机/平板分别需何操作、fixture复制范围、APK/hash、运行入口、预计测试批次、设备临时数据清理。由负责人通知用户开启调试；准备好了再请求，不假定设备已连接。没有设备可先完成其他工作，设备项NOT_RUN。

## 2. 交付与编译

按可自洽功能簇尽量合并实现后集中编译，保留依赖/API/原生隔离必要检查，不逐小功能交接。最终交付docs/coder/D1_DELIVERY_D1-20261005-C02.md（实际日期变化时使用实际candidateId）、复制产物/SHA-256、源码manifest/快照、精确依赖与许可证、全部实验结果和完成矩阵。构建不等于设备通过。

真机请求独立保存docs/coder/D1_DEVICE_TEST_REQUEST_V1.0.md。整包完成后停止修改候选，由负责人统一交tester；关键阻断仍在时如实提交补齐状态，不冒称D1退出或启动M0。所有安全和模型质量门禁保持不变。
