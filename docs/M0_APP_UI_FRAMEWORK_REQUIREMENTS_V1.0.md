## 1. M0 目标与边界

M0 同时交付：原 API/core/Fake/TestKit/sample-host，以及**可运行、可导航、可演示的正式 Flutter App 全页面 UI 框架**。使用同一个后续继续开发的 App 工程与公共组件，不新建用完即弃的纯展示 App，不把原生 sample-host 改名充当 Flutter 产品。

- 视觉及交互依据：[VideoKit UI PPT V1.0](ui/VideoKit_UI_V1.0/output/VideoKit_APP_UI_Design_V1.0.pptx)。深空蓝、青绿操作强调、紫色选区、克制科幻感、清晰层级、手机/平板布局及全部页面为目标样式。
- 用Flutter ThemeData/ThemeExtension、集中Token及公共组件实现自有VideoKit Theme；浅深/系统跟随/持久化/可访问性可真实演示，当前不引入SkinKit。
- 按PPT视觉使用自有Token/组件参数，不实现商业主题SDK/主题包/商城。无法表达的差异列PPT页/组件/限制交评审，不静默偏离既定视觉。
- M0 UI 可用 Fake/测试数据驱动；真实视频、图片解码、多实例、编辑、AI 和导出仍按 M1–M6 实现并逐步接回，M7 验原生 SDK/Browser，M8 验完整 App 真实功能，不等到 M8 才搭 UI。
- 只实施 Android 手机/平板，Apple/Windows 继续保留结构兼容设计与 M9 验证，不能从 Flutter 页面可运行推断四平台媒体或 SkinKit 适配已通过。

## 4. 后续功能接回机制

UI页面依赖 App 级 Controller/ViewModel 与稳定服务端口：Playback、Image、MultiView、EditProject、Tracking、Export、LocalSource/Output。端口围绕已冻结 VideoKit API/Fake 契约建立，不引入第二套语义不同的播放器状态机。

M0 使用开发依赖注入接入 Fake 实现和UI专用fixture；后续每个里程碑用真实 Adapter 替换相应端口，页面与公共组件复用，不整页重写。原生播放/编辑状态仍为真实能力唯一权威，Dart模拟时钟不得与真实状态同时控制一个会话。

每个能力必须维护 `DEMO / REAL / UNSUPPORTED` 来源标记及版本能力报告。尚未实现的功能可在开发演示中模拟，在真实模式应禁用并说明原因，不能自动回退Fake再显示成功。混合接线必须在开发模式明确标注，真实验收只统计对应REAL证据。

| 阶段 | 必须接回M0 UI的真实能力 | UI阶段退出证据 |
| --- | --- | --- |
| M1 | 本地源、播放、Seek、轨道、状态、显示目标 | 同一播放页面改为REAL；错误/权限/释放回归 |
| M2 | 静态/动态图、变换、HostAction | 同一图片/导航UI；无关控件隐藏 |
| M3 | 多会话、预算、唯一声音、降级 | 同一多画面；真实槽状态与资源回收 |
| M4 | 工程/片段/重排拼接/预览计划 | 同一编辑UI；源不变与PTS/恢复 |
| M5 | 手动打码/自动跟踪/纠正 | 同一目标UI；真实质量/LOST/安全阻断 |
| M6 | Sink/导出/验证/取消/提交 | 同一导出UI；真输出与终态/资源 |
| M7 | 版本化SDK/原生宿主/Browser集成 | App不吸收Browser业务；核心不依赖Flutter/SkinKit |
| M8 | 全部页面真实能力联调、Release与适配回归 | 发布主流程无Fake；手机/平板矩阵和许可完整 |

后续里程碑的coder交付必须包含“已接回页面/真实端口/仍为Demo的项目/截图与用例”矩阵；tester同时验UI与真实能力，避免做完核心后留到M8才接页面。不会把上述增量接线解释成多个功能删减发布版本。
