## 1. 原需求覆盖方式

原始31节分别登记章节入口，并对其代码块之外每个项目符号/编号条款建立来源行ID和独立TC-ID，保留原文/位置，覆盖数见文档整理记录。CSV包含设计、主阶段、阶段内task、验收组、独立用例ID、开发/测试工作单、预期原则、证据/结果。代码示例与正文段落通过章节行纳入，不谎称自动解析已证明全部语义覆盖；正式派发必须人工逐节确认正文/示例字段，必要分裂子用例，登记reviewer，不得以有一行章节就整节PASS。

每行caseDetail要在所属阶段派单前补成setup/授权样本hash/平台/准确输入/预期/正反与故障步骤/清理原返/指标revision；用例尚未细化状态为DESIGN_LINKED_CASE_DETAIL_TO_FREEZE，不是已评审测试。引用原文不把其顶部被撤销SkinKit补充当新强制要求，当前范围由CURRENT_DESIGN_BASELINE裁定。样本执行编号不得覆盖历史运行ID。
