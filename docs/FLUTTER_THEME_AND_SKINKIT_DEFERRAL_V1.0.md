# VideoKit Flutter Theme 与 SkinKit 延后集成决定 V1.0

日期：2026-10-20；用户最新明确决定，覆盖此前“不建立自有 Theme”“M0 必须真实集成 SkinKit/原生桥接”的冲突要求。

## 当前设计决定（未声称已实现）

M0 使用 Flutter 开发自有 VideoKit Theme 与完整正式 App UI，依据已生成 18 页 PPT 的视觉、布局和交互。以 Flutter ThemeData/ThemeExtension 和集中设计 Token 实现颜色、字体、间距、圆角、组件及状态，提供浅色/深色、跟随系统和偏好保存；公共组件统一消费样式，避免页面散落字面量。保持手机/平板、自适应、国际化、RTL、大字体、可访问性和减少动画要求。

允许生成明确标注的固定 seed 本地测试数据演示，Debug/Release 隔离；后续真实媒体功能接回同一 UI。自有 Theme 是 App 层样式实现，不是独立商业皮肤 SDK，不因此新增主题商城、主题包解析器或编辑器。媒体核心继续独立于 Flutter、主题及宿主业务。

## SkinKit 后续条件

当前不引入 SkinKit Android 二进制作为 App UI 依赖，不开发 SkinKit 原生到 Flutter 的桥接/PlatformView 方案，不把 SkinKit 实接、Provider、主题包导入/预览等作为 M0 或当前批次退出门。其供应方资料、来源与历史许可记录保留，现有原生交付不代表已有 Flutter 支持。

等 SkinKit 正式提供 Flutter 支持后，由负责人核实交付版本、Flutter/平台兼容性、许可、功能及性能，再安排独立接入开发和测试需求并集中迁移。当前只保持 App 公共组件和集中样式入口，便于未来适配，不提前实现假定 API、不承诺届时零改动，也不自动设定 M8 必须接入。

## 验收与执行

M0 验收自有 Flutter Theme 的主题切换、持久化、全页覆盖、对比度、各种状态及适配；模拟媒体与真实主题效果分别记录，演示不能冒充真实媒体通过。原 API/Fake/TestKit/sample-host 和全部媒体 P0 不删减。按负责人选择每批 1–3 个里程碑集中开发、自测、冻结、整包测试、集中缺陷修复的方式执行，并向用户汇报批次范围。当前D1未通过/M0未启动，项目暂停；历史候选/任务证据不改。
